# 06 - Data Model

PostgreSQL 16. Conventions for every table unless stated:

- `id uuid` primary key (UUID v7, generated by the server).
- `company_id uuid not null` with index. Every query filters by it.
- `created_at`, `updated_at timestamptz not null`. Soft delete through `deleted_at timestamptz null` where marked (SD).
- Enums are stored as text with check constraints, defined once in `packages/contracts`.
- Money as `numeric(14,2)` + currency code. Durations in seconds as `integer`.
- Foreign keys always indexed.

## 2. Attendance

| Table | Key columns |
|---|---|
| shift_schedules | name, workdays int[] (1 to 7), start_time, end_time, crosses_midnight, grace_minutes, half_day_percent |
| employee_schedules | employee_id, schedule_id, effective_from, effective_to |

| leave_requests | employee_id, type, date_from, date_to, reason, status (pending, approved, rejected, cancelled), decided_by, decided_at, comment |

Constraint: partial unique index on `shifts (employee_id) WHERE state <> 'ended'` guarantees one open shift.

## 3. Tracking

| Table | Key columns |
|---|---|
| activity_segments | id (client UUID), employee_id, device_id, shift_id, started_at, ended_at, duration_s, kind (active, idle, locked), process_name, app_name, domain null, window_title null, key_count, mouse_count, exception (none, call_app, meeting_app, mic), claim (none, break, away_work), received_at, late bool |
| activity_daily_app | employee_id, date, app_name, process_name, category, active_s, idle_s. Unique (employee_id, date, process_name) |
| activity_daily_domain | employee_id, date, domain, category, active_s. Unique (employee_id, date, domain) |
| activity_daily_summary | employee_id, date, tracked_s, active_s, idle_s, productive_s, neutral_s, unproductive_s, key_count, mouse_count |
| productivity_rules | target_type (app, domain), pattern, category (productive, neutral, unproductive), department_id null (null = company default) |
| tracking_exclusions | target_type, pattern |
| activity_exception_apps | process_name, type (call, meeting) |
| tamper_events | employee_id, device_id, type (agent_stopped, extension_missing, clock_changed, binary_mismatch), detail jsonb, occurred_at |
| screenshots (1.1) | employee_id, shift_id, taken_at, object_key, blurred |

`activity_segments` is range-partitioned by month on `started_at`. Indexes: (employee_id, started_at), (shift_id). Primary key (id, started_at). Insert is `ON CONFLICT DO NOTHING` on id for idempotency. `date` in rollups is the attendance date.

## 8. Retention defaults

| Data | Retention | Configurable |
|---|---|---|
| activity_segments (raw) | 90 days | yes |
| Daily rollups and attendance | Unlimited | yes |
| window_title, page title (if enabled) | 30 days | yes |
| Screenshots (1.1) | 30 days | yes |
| login_events | 1 year | yes |
| audit_logs, mail_audit | 2 years | yes |
| notifications | 90 days | yes |
| CRM data | Unlimited | no |

## 9. Key relations

```text
company 1-n department 1-n team 1-n employee
employee 1-n device 1-n session
employee 1-n shift 1-n shift_break
shift 1-n activity_segment  ->  daily rollups (employee, date)
employee 1-n attendance_day
employee 1-n lead (owner) 1-n timeline / call_log / note / appointment / task
target n-1 assignee (employee | team | role) ; target 1-n target_progress
mailbox n-n employee (mailbox_assignments) ; mailbox 1-n thread 1-n message
```
